# LLM call-site inventory (Phase 0.5)

Base: branch `chore/remove-marketing` (cb895d3dc), which sits on `feature/prd-v7-inbox-zero-parity`
(upstream merged 2026-11-12). Generated by searching `apps/web` and `packages` for `createGenerateObject`,
`createGenerateText`, `chatCompletionStream`, `toolCallAgentStream`, and raw `generateText`/`generateObject`/
`streamText` from the `ai` package (Vercel AI SDK v7). Tests and evals are excluded. No call sites exist in `packages/`.

All calls go through `apps/web/utils/llms/` (`index.ts` helpers, `model.ts` provider selection,
`use-cases.ts` use-case registry). OpenRouter is already a supported provider (`Provider.OPENROUTER`,
`OPENROUTER_API_KEY`, `DEFAULT_LLM_PROVIDER`).

Decisions:
- **R1**: replace with the CategorAIze service (behind a per-feature switch that restores the LLM path).
- **R2**: stays on the external LLM via OpenRouter (CategorAIze may add context).
- **Keep (LLM)**: an original feature that needs free-text generation or reasoning the three algorithms cannot
  do. It stays on OpenRouter, unchanged, so the feature keeps working. These are the "fits neither" cases.
- **Not AI**: a settings check, not a feature.

## Phase 5 status

Everything below runs only while `CATEGORAIZE_ENABLED` is on. With it off, the app behaves like the original.

| Feature | Switch (default on) | Now | Code |
| --- | --- | --- | --- |
| Rule matching | `CATEGORAIZE_RULE_MATCHING` | **Cascade.** The service (`/api/v1/choose-rule`) matches each rule by its best short description. Built-in rules get extra English and Filipino descriptions. The reply rule (To Reply / Conversations) competes only when the Bi-LSTM-CRF finds a request or the email asks a question. The service returns a confidence verdict; unsure emails go to the original LLM selector only with external-AI consent. Settings are tuned in `fastapi_core/app/data/matching_params.json`. | `utils/categoraize/rule-matching.ts`, `fastapi_core/app/algorithms/rule_matcher.py` |
| Reply Zero status | `CATEGORAIZE_REPLY_STATUS` | **Cascade.** The service (`/api/v1/thread-status`) decides TO_REPLY / AWAITING_REPLY / FYI / ACTIONED from tagger signals (requests, questions, promises, ownership, thanks). Unsure threads go to the original LLM classifier only with consent; otherwise the local answer is used, so Reply Zero works without external AI. | `utils/categoraize/thread-status.ts`, `fastapi_core/app/algorithms/thread_status.py` |
| Cold email | `CATEGORAIZE_COLD_EMAIL` | After the original deterministic checks (whitelist, same org, learned senders, prior contact), the email is cold only if a cold-outreach description beats every legitimate kind of email. | `utils/categoraize/cold-email.ts` |
| Smart categories (senders) | `CATEGORAIZE_SMART_CATEGORIES` | The sender's address plus up to 3 recent subjects and snippets are matched against category centroids, or descriptions until a centroid exists. A manual recategorization runs Rocchio, stored in `CategorizeSenderCategoryCentroid` / `CategorizeSenderEmbedding`. | `utils/categoraize/sender-categories.ts` |
| Summaries (Summarise button, digest) | `CATEGORAIZE_SUMMARIES` | Extractive: up to 2 original sentences (`/api/v1/summarize`). | `app/api/ai/summarise/route.ts`, `utils/ai/digest/summarize-email-for-digest.ts` |
| Drafts and follow-up drafts (R2) | n/a | They stay on OpenRouter. They need the user's optional external-AI consent (off by default; Settings → External AI processing). The draft prompt gets a short `categoraize_analysis` block (language, requests, dates found in the newest email). | `utils/categoraize/consent.ts`, `draft-context.ts`, `utils/reply-tracker/generate-draft.ts`, `utils/follow-up/generate-draft.ts` |
| Attachment filing (Drive / OneDrive) | n/a | Stays on OpenRouter. Needs the same external-AI consent: with it off, attachments are skipped before download and filing replies are not sent to the LLM. | `utils/drive/filing-engine.ts`, `utils/drive/handle-filing-reply.ts` |

**When the service fails:** an R1 feature falls back to the original LLM path only for users who turned on external AI. For everyone else it errors instead, so no email goes to the external provider without consent (`utils/categoraize/features.ts`).

**Still on the external LLM without a consent check:** the "Keep (LLM)" features below (assistant chat, prompt-to-rules, and so on). This needs a decision in Phase 8.
